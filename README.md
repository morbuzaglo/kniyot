# הקניות שלי — PWA לניהול קניות לבית

אפליקציית ווב בעברית (RTL), שמותאמת קודם כול לאייפון. האפליקציה מאפשרת לחפש מוצרים, לבנות רשימות קניות, לעבור על הרשימה ב"מצב קניות" ולשתף אותה בוואטסאפ כטקסט, כתמונות או כ-PDF. היא עובדת גם בלי אינטרנט, ללא חשבון וללא שרת.

> **מצב הקטלוג:** הקטלוג שמגיע עם הקוד הוא **קטלוג דוגמה** (127 מוצרים גנריים, ללא ברקודים וללא תמונות). הוא מסומן בבירור באפליקציה. כדי לקבל מוצרים אמיתיים מריצים את תהליך הייבוא (סעיף 3). בסביבת הפיתוח לא הייתה גישה לאתרי הרשתות, ולכן לא הופק כאן קטלוג אמיתי.

## 1. ארכיטקטורה בקצרה

```
importer/  (Node, רץ על מחשב/CI — לא בדפדפן)
  ├─ sources/      הורדת קובצי PriceFull מהרשתות (שקיפות מחירים)
  ├─ lib/xml       פענוח XML/gz
  ├─ lib/normalize ברקוד (GTIN), שם, מותג, גודל קנוני
  ├─ lib/categorize סיווג למחלקות סופר לפי מילות מפתח
  ├─ lib/merge     איחוד לפי ברקוד + התאמה זהירה ללא ברקוד
  ├─ lib/off       העשרה אופציונלית: תמונות מ-Open Food Facts
  └─ lib/output    → app/catalog/manifest.json + products-N-<hash>.json (+ img/)

app/  (סטטי לחלוטין — כל אחסון HTTPS)
  ├─ index.html, css/, icons/, manifest.webmanifest
  ├─ sw.js         Service Worker: מעטפת + קטלוג במטמון, תמונות קטלוג במטמון מוגבל (300)
  └─ js/
     ├─ catalog.js  טעינת הקטלוג וחיפוש (עברית, כתיב חלקי, טעויות כתיב, ברקוד)
     ├─ db.js/store.js  IndexedDB: רשימות, פריטים, תמונות (Blob), מועדפים, היסטוריה, מוצרים אישיים
     ├─ share.js/pdf.js  טקסט, תמונות PNG בעמודים, PDF (JPEG לכל עמוד)
     ├─ backup.js   גיבוי/שחזור JSON עם גרסה ו-SHA-256
     └─ main.js/ui.js  מסכים
```

**הפרדה בין ציבורי לאישי:** הקטלוג הוא קבצים סטטיים שאפשר להפיץ. כל המידע האישי (רשימות, הערות, מועדפים, צילומים) נשמר רק ב-IndexedDB של המכשיר, ושום דבר לא נשלח לשרת.

**תמונות של פריטים ברשימה** נשמרות כ-Blob ב-IndexedDB ברגע שהפריט נוסף. בזכות זה הרשימה זמינה גם בלי אינטרנט, ואפשר לצייר את התמונות על canvas בזמן השיתוף. תמונות הקטלוג מתארחות על אותו דומיין כמו האפליקציה, ולכן ה-canvas לא "מזדהם" ואפשר לייצא ממנו קבצים.

**טכנולוגיות:** JavaScript נקי עם מודולי ES, בלי שלב build ובלי ספריות. גם תהליך הייבוא לא דורש תלויות (sharp לכיווץ תמונות הוא אופציונלי).

## 2. הרצה מקומית ופריסה

```bash
# הרצה מקומית
python3 -m http.server 8080 --directory app      # או: npx serve app
# פתחו http://localhost:8080
```

**פריסה:** מעלים את התיקייה `app/` לכל אחסון סטטי עם HTTPS. Service Worker, Web Share ו-crypto.subtle דורשים HTTPS. אפשרויות:
- **GitHub Pages:** ב-`.github/workflows/deploy.yml` מוגדרים ייבוא שבועי ופריסה אוטומטית. מפעילים Pages ← Source: GitHub Actions.
- **Netlify / Cloudflare Pages:** תיקיית הפרסום היא `app`, ואין פקודת build.

**התקנה באייפון:** פותחים את הכתובת ב-Safari ← כפתור שיתוף ← "הוספה למסך הבית". מומלץ להשתמש באפליקציה מהמסך הבית: כך iOS לא מוחק את הנתונים אחרי 7 ימים בלי שימוש, והאפליקציה נפתחת במסך מלא. שימו לב שהאחסון של Safari והאחסון של האפליקציה במסך הבית נפרדים. כדי להעביר ביניהם רשימות משתמשים בגיבוי ושחזור.

**עדכון גרסה:** קבצי האפליקציה מוגשים מהמטמון, והגרסה החדשה נטענת ברקע ומופעלת בפתיחה הבאה. בשינוי גדול כדאי להעלות גם את `VERSION` ב-`app/sw.js`.

## 3. ייבוא הקטלוג

**מקורות:** קובצי המחירים שהרשתות מחויבות לפרסם לפי חוק המזון (שקיפות מחירים). מהקבצים לוקחים רק ברקוד, שם, יצרן וגודל. מחירים לא נשמרים.

| רשת | מקור | הערות |
|---|---|---|
| שופרסל | `prices.shufersal.co.il` (קובצי PriceFull) | עמוד ציבורי עם קישורים להורדה |
| רמי לוי | `url.publishedprices.co.il`, משתמש ציבורי `RamiLevi` | ללא סיסמה, כפי שמפורסם לציבור |
| אושר עד | `url.publishedprices.co.il`, משתמש ציבורי `osherad` | כנ"ל |

```bash
node importer/import.mjs                          # כל המקורות, 3 סניפים לכל רשת
node importer/import.mjs --max-stores 8           # יותר סניפים = כיסוי רחב יותר
node importer/import.mjs --sources shufersal
node importer/import.mjs --enrich-off --off-limit 2000   # תמונות מ-Open Food Facts לפי ברקוד
node importer/import.mjs --from-dir ./downloads   # קבצים שהורדו ידנית: downloads/shufersal/*.gz וכו'
npm install sharp   # אופציונלי: מכווץ תמונות ל-400px
```

**מה התהליך עושה:**
- **אפשר להריץ אותו שוב ושוב.** מאגר האב נשמר ב-`importer/data/catalog-db.json`. כל הרצה מעדכנת מוצרים קיימים, מוסיפה חדשים ושומרת את `firstSeen`, `lastSeen` ו-`updated`. מוצרים שלא נראו 120 יום (`--stale-days`) יוצאים מהתצוגה.
- **איחוד:** מוצרים עם אותו ברקוד מאוחדים גם כשהם מגיעים מרשתות שונות. ברקוד שונה נשאר מוצר שונה, ולכן 1 ליטר ו-2 ליטר, או 1% ו-3%, לא מתאחדים. מוצר בלי ברקוד (קוד פנימי של רשת) מתאחד רק אם השם בלי הגודל, המותג והגודל הקנוני **זהים**. מוצר בלי מותג או בלי גודל לא מתאחד בכלל.
- **דוח:** הדוח נשמר ב-`importer/data/import-report.json` וכולל, לכל מקור: מצב, קבצים, פריטים, נוספו/עודכנו/אוחדו, ושגיאות. אותו מצב מוצג גם באפליקציה תחת הגדרות ← "קטלוג וכיסוי".
- **מקור חסום או לא זמין:** המקור מדווח כ"לא זמין" והייבוא ממשיך עם המקורות האחרים. תשובות 401, 403 ו-429 מדווחות ולא נעשה ניסיון לעקוף אותן.
- **תיקונים ידניים:** בקובץ `importer/data/overrides.json`, בצורה `{ "b:7290...": { "cat": "dairy", "name": "..." } }`.
- **קטלוג דוגמה:** `node importer/sample-catalog.mjs` (מסומן `isSample`).

**מגבלות של הייבוא:** קובצי המחירים לא כוללים תמונות או קטגוריות. הקטגוריה נקבעת לפי מילות מפתח בשם, ולכן היא לא מושלמת. תמונות מגיעות רק מ-Open Food Facts, וכיסוי המוצרים הישראליים שם חלקי. תמונות מאתרי הרשתות לא נלקחות, כי זכויות השימוש בהן לא ברורות. שמות המוצרים בקבצים מקוצרים לפעמים. Node לא משתמש בהגדרות proxy של המערכת כברירת מחדל, ולכן ב-Node 22.21 ומעלה צריך להגדיר `NODE_USE_ENV_PROXY=1` מאחורי proxy. ייתכן גם שהאתרים חוסמים כתובות IP מחוץ לישראל, למשל ב-GitHub Actions.

## 4. שיתוף בוואטסאפ: מה נתמך באייפון

- **טקסט:** אפשר דרך `navigator.share({text})` (גיליון השיתוף של iOS), להעתיק, או לפתוח קישור `wa.me` שמסומן במפורש "טקסט בלבד".
- **תמונות ו-PDF:** נוצרים ב-canvas, כך שעברית ו-RTL מוצגים בדיוק כמו בדפדפן. רשימה ארוכה מתחלקת לעמודים (תמונות של 1080px, עד 1920px גובה) במקום להצטופף לתמונה אחת. הקבצים משותפים דרך `navigator.share({files})` (Web Share Level 2, נתמך ב-Safari ובאפליקציה ממסך הבית). המשתמש בוחר בעצמו את וואטסאפ ואת הצ'אט, ואין שליחה אוטומטית.
- **דרישת לחיצה של Safari:** שיתוף חייב לקרות בתגובה ישירה ללחיצה. לכן האפליקציה מכינה את הקבצים ומנסה לשתף מיד. אם Safari חוסם את השיתוף, הכפתור הופך ל"שיתוף N תמונות" ונדרשת לחיצה נוספת.
- **כשאין תמיכה:** מוצגות התמונות עצמן (לחיצה ארוכה ← "שמירה לתמונות") וקישורי הורדה.
- השיתוף הוא **צילום מצב**, וזה כתוב גם בקבצים עצמם. אין סנכרון חי ואין קישור לרשימה משותפת.
- מגבלה: הטקסט ב-PDF הוא חלק מהתמונה, ולכן אי אפשר לבחור אותו או לחפש בו.

## 5. אחסון באייפון

- IndexedDB, בלי חשבון. האפליקציה מבקשת `navigator.storage.persist()` (Safari 17 ומעלה), אבל ההחלטה אם לאשר היא של Safari.
- ב-Safari רגיל, iOS עלול למחוק את הנתונים אחרי 7 ימים בלי שימוש. באפליקציה ממסך הבית זה לא קורה. מחיקת נתוני אתרים בהגדרות iOS מוחקת את הכול בכל מקרה, ולכן יש **גיבוי** (הגדרות ← ייצוא גיבוי) שאפשר לשמור ב"קבצים" או ב-iCloud.
- **גיבוי:** קובץ JSON עם `format`, `version`, `sha256` ותמונות ב-base64. בשחזור הקובץ נבדק: הפורמט, הגרסה, המבנה והתאמת ה-SHA-256. קובץ שנפגם או שונה נדחה.

### מה מומש ונבדק אוטומטית (Chromium בתצורת iPhone)
- חיפוש: טעות כתיב (חלבב, פסתה), כתיב חלקי (קוטג), שם ומותג, ברקוד.
- הבחנה בין גדלים: 1 ליטר ו-2 ליטר מוצגים בתג גודל בולט עם אזהרת "יש N גדלים/סוגים", ונשמרים כשני פריטים נפרדים. בגיליון המוצר מופיעות גם הווריאציות האחרות.
- הוספה בלחיצה בלי לאבד את החיפוש. כמות, הערה, הערות מהירות והעדפת תחליף נשמרות.
- מוצר ידני עם תמונה, חיפוש לפי הברקוד שלו.
- הרשימה נשמרת אחרי סגירה ופתיחה מחדש, מקובצת לפי מחלקות. הסרה עם ביטול. מצב קניות: פריט שנקנה עובר לתחתית, וההתקדמות מתעדכנת.
- **בלי אינטרנט:** האפליקציה, הרשימה, התמונה האישית והחיפוש בקטלוג (מהמטמון) עובדים.
- שיתוף: טקסט עם שם, גודל, כמות והערה. רשימה קצרה יוצאת כתמונה אחת, רשימה ארוכה (28 פריטים) כ-5 תמונות ו-PDF של 4 עמודים, עם עברית תקינה (נבדק ויזואלית). נבדקה גם קריאה מדומה ל-Web Share, כולל חסימה של Safari ולחיצה שנייה.
- גיבוי עם תמונה אישית ← מחיקת כל הנתונים ← שחזור מלא. קובץ גיבוי ששונה נדחה.
- מוצר בלי תמונה מקבל תמונה חלופית. קטלוג שלא נטען מציג הודעה עם "נסה שוב". מקור שנכשל מוצג בהגדרות.
- ייבוא: איחוד לפי ברקוד בין רשתות, אי-איחוד של גדלים ואחוזי שומן, התאמה זהירה בלי ברקוד, הרצה חוזרת בלי כפילויות, מקור שנכשל (גם ברשת אמיתית: מסביבת הפיתוח שלושת המקורות דווחו כלא זמינים, והתהליך הסתיים בקוד 2 בלי לדרוס קטלוג).

### מה לא נבדק בפועל
- **Safari ו-iOS אמיתיים:** הבדיקות רצו ב-Chromium. לא נבדקו על אייפון: גיליון השיתוף של iOS ובחירת וואטסאפ, תצוגת הקבצים בוואטסאפ, התקנה למסך הבית, שטחים בטוחים, התנהגות המקלדת, ו-`storage.persist`.
- **ייבוא מהאתרים האמיתיים:** הגישה לרשת חסומה בסביבת הפיתוח. המבנה של שופרסל ו-publishedprices.co.il מבוסס על המבנה המוכר שלהם ולא אומת כאן. אם המבנה השתנה, התהליך ידווח על שגיאה ברורה.
- העשרה מ-Open Food Facts לא הורצה (מאותה סיבה).
- גופנים: בשרת הבדיקה היה גופן DejaVu. באייפון ישמש גופן המערכת.

### מגבלות ידועות
- הקטלוג המצורף הוא דוגמה. מספר המוצרים האמיתי תלוי בהרצת הייבוא ובמספר הסניפים, ואין הבטחה ל"כל מוצרי הסופר".
- אין סריקת ברקוד במצלמה, כי BarcodeDetector לא נתמך ב-Safari. אפשר להקליד ברקוד.
- אין סנכרון בין מכשירים (בכוונה, בגרסה הראשונה).
- הסיווג למחלקות היוריסטי.
